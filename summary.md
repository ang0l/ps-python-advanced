## Раздел 3. Основы ООП

### Класс и экземпляр

Объектно-ориентированное программирование (ООП) в Python основывается на классах и их экземпелярах.

**Класс** - это шаблон или чертеж для создания объектов. Например, класс "Автомобиль" может содержать такие атрибуты,
как марка и модель. На его основе я можгу созавать конкретные автормобили, такие как Audi A6 или Mercedes GLE.

**Экземпляр** - это конкретный объект, созданный на основе класса. Экземпляр "Заметка" (например, None1) будет
содержать определенные данные, такие как заголовок и содержание.

**Атрибуты** - это данные, хранящиеся в классе. Напримпр, у класса "Стол" есть атрибуты высоты, ширины и материала.

**Методы** - это действия, которые можно выполнить с объектами. Они позволяют взаимодействовать с объектами внутри
класса.

В Python для объявления класса используется ключевое слово `class`. Например, `class Note` описывает, каким образом
будет представлена заметка.

Важной часть ООП является абстракция, которая позволяет описывать только те аспекты объекта, которые важны для моего
приложения.

Таким образом, классы делают программирование более интуитивным, соотвествующим реальному миру, позволяя легко
создавать и работать с объектами в коде.

### Атрибуты

#### Что такое атрибуты

Атрибут - это переменная, принадлежащая объекту или классу, описывающая состояние объекта.

#### Типы атрибутов

**Атриут класса**: задается для класси и применяется ко всем его экземплярамю. Изменения в атрибуте класса отражаются
на всех экземплярах.

**Атрибут экземпляра**: задается для конкретного экземпляра, не зависит от изменений в классе.

#### Поиск атрибута

При обращении к атрибуту (например, `note.title`), Python ищет его сначала в экземпляре, затем в классе, и если не
нейден, тогда поиск идет в родительских классах. Если нигде не найден, возникает ошибка _AttributeError_.

#### Практический пример

1. **Создание класса автомобиля**: описываются марка, модель, год производства и тип транспортного средства.
2. **Создание экземпляра автомобиля**: присваивание значений атрибутам экземпляра и демонстрация того, как изменение
   атрибута класса влияет на экземлпяр.
3. **Изменение атрибутов**: влияние изменения атрибута класса на экземпляры.

### Методы

В этой лекции обсуждались методы в оьъектах программирования. Методы определяются внутри классов и отвечают за
действия, которые может выполнять объект. В отличие от атрибутов, которые хранят данные, методы описывают поведение
объектов.

#### Определение методов

1. Начинаются с ключевого слова `def`.
2. Первым аргументом всегда является `self`, ссылка на экземпляр объекта.
3. Методы могут принимать дополнительные аргументы и возвращать значения как функции.

#### Практический пример

1. Созается класс `Task` с атрибутами `done`(boolean) и `title` (строка).
2. Определяется метод `get_info`, который возвращает значение `title`.
3. Используется `self` для доступа к атрибутам экземпляра в методах.

#### Создание и использование метода

1. Создается экземпляр класса `Task`.
2. Вызывается метод `get_info` через экземпляр.
3. Определяется метод `set_info` для установки `title` при помощи `self`.

#### Взаимодействие с консолью

После заданрия занчения `title` вызывается метод для получения данных и печатается заголовок.

### Self

**Понятие self**: self - это ссылка на текущий обхект класса, используемая для взаимодействия с ним.

#### Механизм работы self

1. При вызове метода, например getInfo, под капотом ищется класс, из которого создан объект.
2. Метод вызывается с передачей ссылки на текущий экземпляр как первый аргумент.
3. Именно поэтому методы принимают экземпляр класса в качестве первого аргумента.

#### Пример с авторизацией

Создаем метод login в классе авторизации, где self изменяет свойство isAuth на True. Такой подход позволяет легко
управлять состоянием объекта, например, авторизовывать пользователя.

#### Альтернативные имена для self

Self — стандартное название, но допустимо использовать другое имя. Python-инструменты могут выдавать предупреждения при
использовании нестандартных имен.

#### Рекомендации:

Использовать self согласно стандартам Python для ясности и читаемости кода. Понимать, что self — это просто соглашение,
но его использование является хорошей практикой.

Таким образом, self обеспечивает возможность манипуляции с текущим объектом класса в методах, и его наименование в
качестве аргумента методов стало стандартом в Python.

### Init

#### Определение и назначепние

`__init__` - это специальный метод класса в Python, который автоматически вызывается при создании нового экземпляра
этого класса. Он не создает объект, а инициализирует его, настраивая свойства объекта.

#### Объявление

Обявляется с использованием двух нижних подчеркиваний: `__init__`. Первый параметр метода всегда `self`, он ссылается
на сам объект.

#### Как работает

Автоматичеки вызывается при создании экземпляра класса. Позволяет задать начальные значения для атрибутов объекта.
Может принимать дополнительные аргументы и использовать `*args` и `**kwargs` для динамического числа аргументов.

#### Пример использования

Без `__init__` мы бы вручную инициализировали каждый атрибут объекта после его создания. С `__init__`, мы передаем
необходимые значения сразу при создании объекта, например:

```
class Note:
    def __init__(self, title, description):
        self.title = title
        self.description = description

note = Note('Заметка', 'Это моя заметка')
```

#### Дополнительные возможности

Атрибуты могут иметь значения по умолчанию. Можно использовать классные переменные для задания дефолтных значений
атрибутов. `__init__` улучшает читаемость и безопасность кода, предупреждая забывание инициализации важных свойств.

#### Заключение

`__init__` делает процессы создания и инициализации экземпляров удобными, облегчая работу с объектами в Python.

### Статические методы

Статические методы - это методы внутри класса, которые не зависят ни от самого класса, ни от его экземпляров. Они
выполняют функции, которые логически связаны с классом, но не требуют доступа к его состоянию. Чтобы куазать, что метод
статический, испльзуют декоратор `@staticmethod`.

#### Примеры использования

Вспомогательные методы: позволяют выполнять задачи, не зависящие от состояния объекта. Например, метод для вычисления
разницы лет между текущим годом публикации книги.

Утилитарные классы: группы логически связанных функций, не имеющих состояния, объединенные в класс для удобства.

#### Применение статических методов

Вызываются напрямую от класса, передавая необходимые аргументы. Используются в ситуациях, когда не требуется доступ к
данным конкретного экземпляра объекта.

#### Как это выглядит в коде

Объявляется класс.  
Определяется статический метод внутри класса с декоратором `@staticmethod`.  
Метод не принимает `self` и выполняет свою задачу, работая с переданными ему аргументами.  
Вызывается метод напрямую через имя класса.

Так как статические методы не имеют доступ к объекту, они служат для задач, которым не нужно состояние объектов, но
которые логически связаны с функциональностью класса.

### Классовый метод

В этой лекции рассматриваются классовые методы в Python, которые занимают промежуточное положение между методами
экземпляра и статическими методами.

**Методы экземпляра** имеют доступ к атрибутам конкретного объекта, обозначаются аргументом `self`.

**Классовые методы**:

- имеют доступ к самому классу, но не к его истантсам, и обозначаются аргументом `cls`;
- полезны для работы с общими данными класса, например, подсчета количества созданных объектов;
- используются для создания альтернативных конструкторов, позволяющих создавать объекты не только стандартным путем.

**Статические методы** не имеют доступа ни к инстансам, ни к классу. Они просто находятся внутри класса как независимые
функции.

Пример использования классового метода: создание пользователя из стоки данных с помощью метода `from_string()`, который
выступает как альтернативный конструктор.

### Встроенные (магические) методы

1. **Метод `__init__`**:
   - это встроенный метод для инициализации объекктов класса;
   - например, в классе `ShoppingList` я могу инициализировать пустой список покупок.
2. **Сравнение объектов**:
   - стандартное сравнение проверяет адреса в памяти;
   - для сравнения содержимого можно переопределить метод `__eq__`;
   - `__eq__` позволяет сравнивать объекты по содержимому, а не только по их местоплоложению в памяти.
3. **Вычисление длины**:
   - метод `__len__` используется для определения длины объекта;
   - Переопределив `__len__`, можно использовать стандартную функцию `len()` для получения длины списка покупок.
4. **Доступ по индексу**:
   - метод `__getitem__` позволяет обращаться к элементакм объекта по индексу;
   - полезен для получения элементов в стиле списка.
5. **Строковое представление**:
   - метод `__repr__` определяет, как объект будет представлен в виде строки;
   - полезен для логирования и отладки, поскольку позволяет выводить внятное строковое представление объекта при вызове
     `print()`.
6. **Расширяемость классов**:
   - переопределение магических методов позволяет использовать стандартные операторы и функции (например, сравнение и
     расчет длины);
   - осознание этих возможностей помогает сделать классы более гибкими и функциональными.

### Property

### Dataclass

В этой лекции расказывается о ключевых преимуществах использования "датаклассов" в Python для упрощения работы с
классами.

**Проблема классического продхода**.  
В стандартном подходе необходимо вручную определять множество методов для класса (инициализация, вывод в строку,

**Решение с датаклассами**  
Использование декоратора `@dataclass` позволяет автоматически генерировать необходимые методы, такие как `__init__`,

- Пример создания объекта, вывода в консоль и сравнения объектов.

**Дополнительные возможности**  
Можно задавать поведение для дополнительных параметров: например, включать или отключать порядок сравнения,

чтобы исключить их из автоматического вывода в логах.

**Облегчение работы**  
Датаклассы существенно упрощают создание и управление классами, что делает код более читаемым и удобным в поддержке.

Заключение: датаклассы в Python позволяют сократить количество шаблонного кода и делают работу с объектами более
эффективной и простой.

## Раздел 4. Декораторы

### Что такое декоратор

#### Определение

Декоратор - это паттерн проектирования, позволяющий обернуть одну функцию в другую для модификации ее поведения. Python
предоставляет синтаксический сахар для декораторов через символ `@`.

#### Основная идея

Имеется функция `say_hello()`, которая выводит "Привет!". Нужно логировать каждый вызов этой функции, добавляя
сообщения о начале и завершении выполнения.

#### Создание простого декоратора

Создается функция `log()`, которая принимает другую функцию как аргумент. В этой функции создается внутреняя функция
`wrapper()`, которая:

- выводит "функция началась",
- вызывает исходную функцию,
- выводит "функция завершилась".

`wrapper()` возвращается как результат `log()`.

#### Использование декоратора

Оборачивается `say_hello()` в `log_decorator()` и сохраняется результат. Вызов обернутой функции приводит к выводу
сообщений о начале и коные, а также сообщения "Привет!".

#### Синтаксический сахар

Вместо ручного оборачивания функций, используйте символ `@` для декорации:

```
@log
def say_hello():
    pass
```

Это автоматически применяет декораток к функции.

#### Преимущества использования декораторов

Упрощение кода за счет улучшенной читаемости и легкости приенения декораторов. Возможность расширения функцинала без
изменения исходного кода функции.

#### Функциональные возможности

Декораторы могут выполнять различные задачи: логирование, аутентификация, кэширование и другое. Это достигается
благодаря обертыванию и модификации поведения исходной функции.

Используя декораторы, разработчики могут легко добавлять новые функциональные возможности к функциям без дублирования
кода и изменения их внутренней логики.

### Декораторы с аргументами

В этой лекции рассматривается использование декораторов для функций с аргументами. Основное внимание уделяется
декорированию функции `add()`, которая принимаает два оргумента типа `float` и возвращает их сумму.

#### Предпосылки

Функция `add(a: float, b: float) -> float` склаывает два числа. Хотим декорировать функцию, чтобы логировать вызов с
аргументами.

#### Создание декоратора @log

Декоратор - функция, принимающая другую функцию. Внутри создается функция-обертка `wrapper()`, принимающая аргументы
через `*args` и `**kwargs`. `wrapper` логирует вызов функции и аргументы.

#### Реализация вызова через обертку

Получаем имя функции через `func.__name__`. Вызов оригинальной функции происходит с переданными аргументами `*args` и
`**kwargs`. Логирование до и после вызова функции.

#### Возврат результата

Обертка возвращает результат вызова оригинальной функции. Декоратор универсален и может использоваться с любой
функцией.

#### Проверка

Функция `add()` декорирована и корректно работает с аргументами. Логируется информация о вызове с результатом.

Таким образом, декоратор `@log` позволяет нам отслеживать вызовы функций и их результаты, независимо от числа и типов
аргументов, что делает его универсальным инструментом для логирования.

### Декоратор классов

#### Зачем нужен декоратор класса

Декораторы класса позволяют модифицировать классы, добавляя к ним новые методы или функциональность, без изменения их
основного кода. Пример использования: добавление метода для форматированного вывода данных объекта.

#### Как работает декоратор класса

**Принцип работы**. Декоратор класса принимает класс в качестве аргумента, модифицирует его поведение и возвращает
модифицированный класс.

**Пример**: декоратор, который добавляет метода `__repr__` для форматированного вывода.

#### Пример создания декоратора

**Исходный класс** `User` с атрибутами `name` и `age`.

```
class User:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age
```

**Создание декоратора `add_repr`**

Декоратор примимает класс (cls) как аргумент. Создает метод `__repr__`, форматирующий вывод информации о классе.
Присваивает метод `__repr__` классу и возвращает модифицированный класс.

```
def add_repr(cls):
    def __repr__(self):
        return f'{cls.__name__}[{self.__dict__}]'

   cls.__repr__ = __repr__
   return cls
```

**Применение декоратора**

Декорируем класс `User` с помощью `@add_repr`. Теперь класс `User` получает новый метод `__repr__` для форматированного
вывода.

```
@add_repr
class User:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age
```

#### Проверка работы

Создается объект `User` и выводится на печать. Благодаря декоратору, вывод объекта будет содержать имя класа и все его
атрибуты в понятном формате.

```
user = User(name='Андрей', age=55)
print(user)  # Output: User({'name': 'Андрей', 'age': 55})
```

#### Итог

Декоратор класса позволяет гибко модифицировать поведение класса. Важно помнить: декоратор изменяет класс, возварщая
его с добавленными или измененными методами.

### Декоратор с параметром

В этом уроке обсуждается, как создать декоратор для функции, который принимает аргументы. Примером служжит функция
`hello`, которую нужно выполнить несколько раз. Для этого создаетя декоратор `repeat`, позволяющий задасть количество
повторений.

#### Создание дополнительной обертки

`repeat` принимает аргумент - количество повторов. Внутри определяем еще одну обертку для нашего декоратора.

#### Определение декоратора

Этот декоратор принимает функцию. Он возвращает враппер.

#### Реализация враппера

Враппер использует аргументы и выполняет функцию несколько раз. Для этого используется цикл `for` с `range(times)`.

#### Пример использования

Декоратор `rqpeat` оборачивеет функцию и запускается. Вызов `hello` прриводит к ее тройному исполнению благодаря

Таким образом, декораторы можно делать более гибкими, добавляя возможность передачи аргументов.

### Упражнение - Декоратор Retry

В этом упражнении я учился создавать декораторы, а именно декоратор Retry, который используется для повторного
выполнения функции в случае ошибки. Ниже представлена основная структура создания такого декоратора.

1. **Описание задачи**: декоратор Retry должен обрабатывать ошибки и повторять выполнение функции заданное количесво
   раз.
2. **Функция для тестирования**: используется функция `unstable()`, которая случайно вызывает ошибку соединения.
3. **Создание декоратора**:
   - **обертка Retry**: Создается функция `retry()`, которая принимает параметр `times`, указывающий количество
     попыток;
   - **основной декоратор**: внутри `retry()` создается декоратор, принимающий саму функцию;
   - **функция-обертка (wrapper)**:
     - принимает `*args` и `**kwargs`;
     - использует цикл для выполнения функции несколько раз, оборачивая в `try-except`;
     - печатает сообщения об удачных и неудачных попытках.
4. **Логика выполнения**:
   - для каждой попытки в диапазоне от 1 до `times` выполняется функция;
   - в случае исключения печатается номер неудачной попытки и пробуется снова;
   - если все попытки исчерпаны - завершение выполнения с соответствующим сообщением.
5. **Тестирование декоратора**  
   Необходимо раскомментировать функцию и выполнить проверку работы декоратора.

Результат: декоратор успешно повторяет попытки выполнения функции до тех пор, пока оне не выполнтся успешно или не
исчерпает количество попыток.

### Wraps

В этой лекции я рассмотрел, как правильно работать с обертками и декораторами в Python, чтобы сохранить исходные данные
функции.

**Проблема с обертками (врапперами)**: при оборачивании функции с помощью враппера, оригинальная функция может потерять
свои метаданные, такие как имя. Вместо этого имя становитися "wrapper".

**Решение с использоваинем декоратора `wraps`**. Чтобы сохранить метаданные оригинальной функции в обертке, необходимо
использовать декоратор `wraps` из модуля `functools`. `wraps` оборачивает враппер и передает ему данные оригинальной
функции.

**Реализация**

- Импорт `wraps` из `functools`.
- Использование `wraps` над функцией в декораторе, передавая туда оригинальную функцию.
- Это обеспечит сохранение имени и других параметров функции, которые могут потребоваться в дальнейшем коде.

**Рекомендация**: всегда использовать `wraps` при создании врапперов в декораторах, чтобы избежать возможных проблем с
потерей данных функции.

**Пример использования**: после имплементации `wraps`, при вызове функции видно, что ее имя и параметры остаются такими
же как у оригинальной.

Таким образом, `wraps` играет ключевую роль в сохранении метаданных функции при исползовании декораторов в Python.

### Дескриптор

#### Введение

В других языках программирования существуют декораторы для атрибутов. В Python вместо них используются дескрипторы -
специальные классы с методами `get`, `set` и `delete`.

#### Что такое дескрипторы?

Дескрипторы - это особый вид классов, которые управляют доступом к атрибутам. Они содержат методы: `get`, `set`,
`delete`.

#### Применение дескрипторов

Например, для контроля значений атрибута, чтобы, например, цена товара не была отрицательной или нулевой.

#### Схема работы

1. **Класс дескриптор**: создается класс `Positive`, который проверяет, что значение атрибута положительное.
2. **Метод `get`**:
   - ипользуется для получения значения атрибута;
   - берет значение из `__dict__` объекта.
3. **Метод `set`**:
   - устанавливает значение атрибута и выполняет проверку;
   - если значение меньше или равно нулю, выбрасывается _ValueError_.

#### Особенности

Дескрипторы позволяют добавлять логику при чтении и установке атрибутов. Они полезны для переиспользования логики в
различных классах. Важно следить за соответствием имен атрибутов между классом-объектом и дескриптором.

#### Преимущества

Дескрипторы заменяют декораторы для атрибутов, предоставляя легкость внедрения и переиспользования логики через
атомарные классы.

Заключение: дескрипторы - это удобный инструмент для управления доступом к атрибутам в Python, расширяющий стандартные
возможности, подобные декораторам в других языках.

### Getattr и Setattr

В этой лекции рассматриваются функции `getattr()`, `setattr()` и `hasattr()`, которые позволяют управлять атрибутами
объектов в Python.

**getattr** используется для получения значения атрибута объекта. Сначала пытается найти атрибут в экземпляре, замем в
классе. Использовать в дескрипторах не следует, так как это может вызвать бесконечную рекурсию.

**setattr** применяется для установки значения атрибута объекта. Принимает объект, имя атрибута и значение.

**hasattr** проверяет наличие атрибута у объекта. Возвращает `True`, если атрибут существет иначе `False`.

Примеры использования:

- для получения и установки атрибутов объекта, например, атрибут `age` для объекта `user`;
- динамическое выполнение команд, как в случае с ботом, где команды `start`, `stop`, `help` могут быть вызваны на
  основе пользовательского ввода.

Эти функции полезны для динамическ4ого доступа к атрибутам, что позволяет писать гибкий и адаптивный код.

### Упражнение - Декоратор limit

#### Цель

2. **Обработка аргументов**.

должен выбрасывается _RunTimeError_.

**Заключение**. Методика и пример использования показывают, как ограничить число вызовов метода с помощью декоратора,

### Классы декораторы

В этом уроке рассматривались декораторы в Python, которые могут быть не только функциями, но и классами. Это особенно
полезно, когда декоратор должен хранить состояние.

#### Классовые декораторы

Декоратор в виде класса должен раелизовывать метод `__call__()`, который обеспечивает вызов. Метод `__init__()` можно
использовать для инициализации состояния, например, отслеживания количества вызовов.

#### Пример реализации

- Создается класс `Limit` с методом `__init__()`, где инициализируестя состояние, например, `self.count`.
- Реализуется метод `__call__()`, который принимает функцию и возвращает обертку `wrapper()`.
- В `wrapper()` используется `*args` и `**kwargs` для передачи аргументов в декорируемую функцию.
- Состояние хранится в самам классе, и его легко можно изменить, что упрощает логическую часть кода.

#### Приемущества классовых декораторов

Явное хранение и управление состоянием. Возможность добавлять дополнительные методы для работы с состоянием, если оно
сложное. Улучшенная читаемасть кода.

#### Когда использовать

Функциональный декоратор подходит, если нет состояния. Классовый декоратор предпочтителен, если нужно хранить и
обрабатывать состояние.

## Раздел 5. Принципы ООП

### О принципах ООП

Объектно-ориентированное программирование (ООП) - это парадигма, основанная на концепции объектов, моделирующих
реальные или бизнес-системы. Применение принципов ООП упрощает поддержку, масштабирование и доработку приложений.

#### Основные принципы ООП

##### Абстракция

Описание объектов с акцентом только на необходимые свойства. Пример: для ноутбука важна функциональность клавиатуры, но
не тактовая частота процессора.

##### Инкапсуляция

Скрытие внутренней раелизации, доступ только к необходимым методам и свойствам. Пример: пользователю доступно включение
ноутбука, но не управление его внутренними процессами.

##### Наследование

Позволяет создавать новый класс на базе существующего с добавлением уникальных свойств. Пример: мабук может быть
наследником базового класса компьютера, добавляя свои свойства.

##### Полиморфизм

Возможность работать с объектами через общий интерфейс, не зная их внутренних структур. Пример: использование разных
операционных систем на ноутбуках через единый интерфейс.

### Инкапсуляция

Сегодня рассмотрен принцип инкапсуляции с практическим примером.

#### Проблема

При разработке банковской системы пользователь имеет публичное свойство `balance`, которое можно изменить напрямую, что
может привести к некорректным данным, например, отрицательному балансу.

#### Решение через инкапсулящию

**Приватные свойства**. Сделать `balance` приватным, добавив в его название два подчеркивания: `__balance`. Это скроет
его от внешнего доступа, и прямое изменение станет невозможным.

**Публичные методы для управления**. `get_balance()` - возвращает текущий баланс. `deposit(amount)` - увеличивает
баланс на заданную сумму, предварительно проверяя, что сумма положительная. Иначе выбрасывает _ValueError_.
`withdraw(amount)` - уменьшает баланс, если хватает средств. Иначе выбрасывает ошибку.

#### Проверка работы

Создается пользователь и через методы изменяется его баланс, например, добавление и списывание средств. Обращение к
приватному свойству напрямую приводит к созданию нового, не связанного с приватным.

#### Подводные камни и ограничения

Использование двойных подчеркиваний не обеспечивает абсолютной приватности. Можно обойти защиту, зная внутреннюю
структуру. Override публичного API с явными нарушениями защиты приведет к предупреждениям и ошибкам кода.

#### Заключение

Инкапсуляция позволяет скрыть детали реализации и защитить данные от некорректного изменения, создавая более надежную и
легкую для поддержки систему.

### Наследование

В этом уроке рассматривается концепция наследования в объектно-ориенттированном программировании (ООП) на примере
создания учбной платформы.

#### Проблема дублирования

Есть два класса: Student и Mentor, оба содержат одинаковые методы инициализации и получения информации, что ведет к
дублированию кода.

#### Решение через Наследование

Созается базовый класс `User`, который будет содержать общие методы и свойства, такие как `__init__()` и `get_info()`.
Классы Student и Mentor наследует от User, что позволяет им испольовать общие методы и свойства, добавляя при этом свои
специфические методы (например, `watch_video()` для студента и `check_homework()` для ментора).

#### Преимущества Наследования

Устраняется дублирование кода.  
Общие свойства и мтоды находятся в одном месте, что упрощает поддержку кода.  
Специфичные методы остаются в наследниках, что делает код более ясным.

#### Пример использования

Создается объект класса `Student`, которому можно вызвать методы `get_info()` и `wathc_video()`, демонстрируя
доступность как унаследованных, так и специфических методов.

#### Дополнительные возможности Наследования

Возможнность множественного наследования: класс может наследовать нескользко других классов. Создание более общик
классов, таких как `Human`, от которого можно наследовать `User`, чтобы расширить функциоанльность.

#### Практическое применение

Наследование удобно, когда объект является частным случаем более общего объекта. Рекомендуется избегать излишне
глубокой и сложной иерархии наследования для поддержания понятности кода.

Таким образом, наследование помогает сделать код более структурированным и уменшьить объем повторяющегося кода.

### Множественное наследование

#### Типы наследования

В Python поддерживается простое наследование (наследование от одного класса). Также возможно множественное
наследование - наследование от нескольких классов одновременно.

#### Практическое применение

Рассмотрен пример "умного дома", который включает в себя два устройства:

- **Освещение (Light)**: имеет метод `turn_on()`, который выводит сообщение "Свет включен".
- **Музыка (Music)**: имеет метод `play()`, который выводит сообщение "Музыка включена".

Создается класс `SmartHome`, котлорый наследуется от обоих классов - `Light` и `Music`.

#### Реализация множественного наследования

Для этого необходимо указывать сразу несколько классов при обхявлении класса `SmartHome` через запятую:

```
class SmartHome(Light, Music):
    def start(self):
        print('Умный домактивен')
        self.turn_on()
        self.play()
```

Класс `SmartHome` наследует методы `turn_on()` и `play()` от классов `Liht` и `Music` соответственно.

#### Проверка работы

Создается объект `SmartHome` и вызывается метод `start()`. Вывод:

```
Умный дом активен
Свет включен
Музыка включена
```

#### Заключение

Множественное наследование позволяет объединять функционал нескольких классов в одном. Такие подходы делают код более
гибким и расширяемым.

В следующем уроке будет рассмотрен случай, когда в унаследованных классах присутствуют одинаковые методы, как Python
справляется с подобными коллизиями.

### Method Resolution Order

Чтобы избежать конфликтов с одинаковыми именами методов в классах, используется метод разрешения порядка (Method
Resolution Order, MRO). MRO показывает порядок, в котором вызываются методы 0из классов при наследовании.

**Переопределение методов**: в дочернем классе можно переопределять методы родительского класса, и при вызове будет
использоваться именно метод из дочернего класса.

**Конфликт методов в нескольких родителях**: если два родительских класса содержат методы с одинаковыми именами,
порядок наследования определяет, какой метод будет вызван первым.

**Method Resolution Order (MRO)**:

- MRO управляет порядком поиска методов в наследуемых классах;
- порядок, указанный при множественном наследовании, определяет последовательность поиска;
- для визуализации MRO можно использовать метод класса, такой как `mro()`.

**Изменение порядка наследования**: поменяв порядок классов в списке наследования, можно изменить, какой метод будет
вызван первым.

**Использоваине super()**: позволяет вызывать методы родительского класса даже при наличии переопределения в дочернем
классе, подробнее об этом разговор будет в другой части.

Таким образом, MRO и правильное использование наследования помогаютуправлять вызовами методов в сложных структурах
классов.

### Super

#### Основные моменты лекции

##### Наследование и переопределение

Связь между родителем и потомком обычно происходит через вызов методов или их переопределение. Наследование часто
применяется, когда нужно не просто переопределить метод, а дополнить его.

##### Пример из интернет-магазина

Создан базовый класс `Order` с методом `process()`, который оформляет заказ. Новый класс `EmailOrder` наследует `Order`
и добавляет дополнительные параметры, например, хранение и отправка e-mail.

##### Вызов метода родителя

Использование `super()` для вызова метода родителя. Вызов `super().process()` позволяет сначала выполнить метод
`process()` из `Order`, а затем дополнить его.

##### Приныцип DRY (Do Not Repeat Yourself)

Наследование позволяет избегать дублирования кода, сохраняя читаемость и следуя принципу DRY.

##### Переопределение конструктора

В `EmailOrder` конструктор `__init__()` может быть дополнен новыми параметрами (например, e-mail). Использование
`super()` в `__init__()` для передачи параметров базовому классу `Order`.

##### Возможность невызывать конструктр

Конструктор базового класса можно не вызывать, однако это можетпривести к нестабильности и предупреждениям.

##### Практическое применение суперконструкции

Всегда следует использовать `super()` для корректного обращения к родительских методам и конструкторам.

Эти упомянутые принципы и меодв делают код боле структурированным, компактным и поддерживемым. Использование `super()`
является стандартом, который обеспечивает гибкость при работе с наследованием.

### Упражнение - Курсы

Упражнение на тему наследования в ООП.

**Создание базового класса**. Базовый класс называется `Course` с атрибутами (цена - float, название - str,
длительность - int). Метод `get_price()` возвращает цену курса. Метод `get_info()` возвращает информацию о курсе
(название, цена, длительность).

**Создание подклассов**. Подкласс `AI`, наследуется от базового класса `Course`. Дополнительный метод `get_credit()`
расчитывает и возвращает рассрочку (цена делится на длительность). Подкласс `Project`, наследуется от базового класса
`Course`. Добавляется атрибут `project_name` для названия проекта. Метод `get_credit()` расчитывает рассрочку. Метод
`get_project_info()` возвращает информацию о проекте (название проекта).

**Создание экземпляра класса**. Пример создания объекта курса с проектом, используя класс `Project`. Вызов методов
`get_info()` и `get_project_info()` для демонстрации получаемой информации.

**Рекомендации**: избегайте глубокого наследования во измежание осложений при изменении в будущих версиях; проблема
дублирования кода будет обсуждаться в последующих лекциях.

### Mixins

#### Введение в миксины

Миксины - это обычные классы, которые добавляют функциональность другим классам. Они выделяются в отдельную группу и
обычно имеют окончание `Mixin`. Миксины, как таковые, не существуют самостоятельно, их нельзя инициализировать
отдельно.

#### Зачем нужны миксины

Они добавляют поведение и функциональность в классы без кардинальных изменений. Используются, когда нет необходимости в
самостоятельной инициализации класса.

#### Применение миксинов

Введение нового класса (например, `CreditMixin`), который обладает определенным поведением (например, `calc_credit()`).
Обычно не имеют метода `__init__()`, добавляют только поведение.

#### Практическое использование

Перенос функциональности (например, расчета цены кредита) в миксин для устранения дублирования кода. Использование
миксина в других классах (`AI`, `Project`) для добавления нужного поведения. Проверка работоспосоности и корректности
внедрения миксина без нарушений в программе.

#### Завершение

Миксины - это удобный способ добавления специфичного поведения без создания независимых классов. Они помогают избежать
дублирования кода и упрощают поддржку классической архитектуры кода.

### Полиморфизм

#### Определение полиморфизма

Полиморфизм происходит от греческого слова, означающего "многоформенный". В программировании - это возможжность
объектов разного типа вести себя по-разному, используя один и тот же метод.

#### Пример встроенного полиморфизма

Метод `len()` в Python демонстрирует полиморфизм, посскольку может вычислять длину объектов разных типов (строки,
списки, словари).

#### Реализация полиморфизма в классах

Создаются классы с одним и тем же методом, например, `pay()`. Класс `CardPayment` с методом `pay()`, который выводит
сообщение об оплате картой. Класс `CryptoPayment` с аналогичным методом `pay()` для оплаты криптовалютой.

#### Преимущества полиморфизма

Позволяет обрабатывать объект списка различных платежей (например, `CardPayment`, `CryptoPayment`, `ApplePayment`) с
помощью одного метода `pay()`. Исключается необходимость знать детали реализации этих методов для каждого типа.

#### Duck Typing и наследование

В Python действует "утиновая типизация": если нечто ведет себя как утка, значит - это утка. Для обеспечения
корректности и обязательности метода `pay()`, рекомендуется использовать наследование. Создается базовый класс
`Payment` с методом `pay()`; в случае, если метод не реализован, выбрасывается _NotImplementedError_.

#### Заключение

Полиморфизм упрощает обработку объектов с различными внутренними реализациями, позволяя использовать единый интерфейс.
Для соблюдения структуры и предотвращения ошибок, наследование остается предпочтительным способом в реализации
полиморфизма.

### Композиция

Сегодня обсуждалось, почему наследование не всегда лучшее решение при проектировании программных систем и как
использовать композицию в качестве альтернативы.

#### Проблема наследования

Наследование применяется, когда объекты являются часными случаями друг друга. Пример: машина - частный случай
транспорта, но не двигателя. Изменения в базовом классе могут повлиять на производный класс, что не всегда желательно.
Пример с уведомлениями: изменение в логике `Notification` затрудняет его использование для специфичных подтипов, таких
как `EmailNotification`.

#### Композиция

Вместо наследования можно использовать композицию, где объект включает в себя другой объект и делегиует ему функции.
Например, `Notification` может содержать объект `sender`, который отвечает за отправку сообщений, будь то e-mail, SMS и
т.д.

#### Когда использовать что

Наследование подходит для жестко связанных классов, где изменение базового класса логично влияет на производный
(например, пользователь и админ). Композиция предпочтительна, когда сущности не должны влиять друг на друга, чтобы
поддерживать модульность и гибкость.

#### Рекомендации

Избегайте чрезмерного использования наследования, так как это может запутать код.  
Используйте композицию для усиления слабой связанности между классами.  
Избегайте глубоких иерархий наследования, чтобы уменьшить сложность поддержки и изменения кода.

### Абстрактный класс

#### Краткое содержание лекции

##### Проблема общей функциональности

Нужно добавить общую функциональность, такую как метод логирования, в классы `MemoryStorage` и `FileStorage`.

##### Ограничения протоколов

Протоколы не позволяют создавать общую функциональность, которая бы автоматически наследовалась.

##### Решение с помощью абстрактных классов

Абстрактные классы наследуются от `ABC` (Abstract Base Class). Это позволяет хранить общую функциональность (например,
метод логирования) в базовом классе, заставляя наследников реализовать свои специфические методы, такие как `save()` и
`load()`. Абстрактные методы обозначаются декоратором `@abstractmethod`, подсказывющим, что метод должен быть
реализован в классах-наследниках.

##### Особенности абстрактных классов

Абстрактный класс не может быть инициализирован сам по себе. Наслдедники обязаны реализовывать все абстрактные методы.
Общие реализуемые методы (например, метод логирования) могут быть использованы наследниками.

##### Когда использовать астрактные классы и протоколы

**Протоколы** используются для указания типов или сигнатур методов без конкретной реализации.  
**Абстрактные классы** используются, когда необходима общая функциональноссть с обязательной реализацией определенных
методов в наследниках.

##### Пример использвания

Изменения на абстрактный класс позволяют использовать метод логирования в `save()`, сохраняя общую функциональность.
Обятательное требование к классам `MemoryStorage` и `FileStorage` - реализовать свои методы `save()` и `load()`.

Эта структура позволяет сделать код более эффективным и повторно использовать функциональность без дулирования в каждом
классе.

## Раздел 6. SOLID и архитектура

### О Solid

В этом уроке объясняется, что объектно-ориентированное программирование (ООП) не всегда обеспечивает правильную
структуру кода для создания поддерживаемых и гибких приложений. Для решения этой задачи существуют принципы SOLID,
набор из пяти фундаментальных принципов, которые помогают проектировать приложения в ООП.

SOLID расшифровывается как:

S - принцип единой ответственности (Single Responsibility Principle).  
O - принцип открытости и закрытости (Open/Closed Principle).  
L - принцип подстановки Барбары Лисков (Liskov Substitution Principle).  
I - принцип разделения интерфейса (Interface Segregation Principle).  
D - принцип инверсии зависимости (Dependency Inversion Principle).

Эти принципы помогают создавать приложения, которые легче поддерживать и развивать. Хотя отказ от этих принципов
возможен, он может привести к неэффективной архитектуре, дублированию кода и непрактичной структуре приложения. В
дальнейших уроках будут подробно рассмотрены каждый из этих принципов с практическими примерами. Начнется с изучения
принципа единой ответственности.

### Single Responsibility Principle

Итак, что же такое принцип единой ответственности (Single Responsibility Principle) в программировании.

#### Принцип

Кдасс должен иметь только одну причину для изменения, те есть он должен выполнять лиш одну функцию.

#### Плохой пример

Класс `Order`, который:

- Рассчитывает общую сумму заказа;
- Сохраняет данные в базу;
- отправляет подтверждающее e-mail.

Проблема: методы сохранения и отпрвки e-mail не относятся напрямую к задаче обработки заказа.

#### Анализ

Рассчитать общую сумму заказа - логичная задача для класса заказа. Сохранение в базу данных и отправка e-mail - это
задачи, которые должны быть у отдельных классов, независимых от `Order`.

#### Решение

Разделить обязанности на отдельные классы:

- **`OrderRepository`** - класс, ответственный за сохранение Ordersв базу данных;
- **`EmailService`** - класс, ответственный за отправку e-mail.

#### Преимущества

Упрощение управления изменениями: изменения в одном аспекте системы ене затрагиваю другие. Повышение читабельности и
поддержки кода: каждый класс выполняет четка определенную задачу.

Таким образом, соблюдение принципа единой ответственности приводит к более чистой архитектуре и упрощает поддержку
кода.

### Open Closed Principle

На этом уроке изучался принцип открытости-закрытости из аббревиатуры SOLID, обозначаемый буквой O. Этот принцип гласит,
что классы должны быть открыты для расширения, но закрыты для модификации.

#### Что это значит?

При добавлении нового функционала класс не должен изменяться. Вместо этого он должен расширяться за счет новых классов
или компонентов.

#### пример проблемы

Создается калькулятор скидок `DiscountCalculator`, который рассчитывает скидки на основе пользовательского типа
(user_type). При появлении новых типов пользователя, например, "Гости", приходится модифицировать существующий класс.

#### Решение

Заветси отдельную политику скидок (`DiscountPolicy`) и создать абстрактный метод `apply_discount`. Разрабатывать
классы-политику для различных типов скидок (например, `NoDiscount`, `StudentDiscount`, `VipDiscount`).
`DiscountCalculator` теперь работает с объектами `DiscountPolicy` и не зависит от конкретных типов пользователей.

#### Преимущества

Простое добавление новых типов пользователей и скидок (например, `GeustDiscount`) без изменения внутренней логики
`DiscountCalulator`. Код становится более гибким и поддерживаемым, так как каждая новая политика вводится как отдельный
класс.

Таким образом, принцип открытости-закрытости помогает проектировать гибкие системы, где функциональность может
расширяться без нарушения существующего кода, что делает код более устойчивым к изменениям и улучшает его поддержку.

### Упражнение - Уведомления

**Результат**: тепрь `NotificationService` может легко использовать новые нотификаторы, соответствуя принципу
открытости/закрытости: добавление нового функционала без изменения существующего кода.

Итог: переписан код, интегрировав лучшие практики объектно-ориентированного программирования для оеспечения гибкости и
устойчивости системы уведомлений.

### Liskov Substitution Principle

Принцип подстановки Барбары Лисков (LSP) является одним из ключевых принципов SOLID. Он гласит, что объекты дочерних
классов должны быть взаимозаменяемы с объектами базовых классов без нарушения работы программы.

#### Основные идеи

**Взаимозаменяемость**. Если используется базовый класс (например, `User`), любой наследник (например, `PremiumUser`)
должен работать вместо него ез ошибок.  
**Сохранение поведения**. Методы наследников должны поддерживать поведение, заложенное в базовом классе. Например, если
меод базового класса доавляет бонусы, то и наследник должден добавлять бонусы, а не изменять логику.  
**Повторение общего контракта**. Каждый наследуемый класс должжен сохранять смысл и поведение методов базового класса.

#### Пример

Базовый класс `User` имеет метод добавления бонусов. `PremiuvUser` переопределяет этот метд, добавляя бонусы в двойном
размере, что соответствует принципу LSP. `BannedUser`, напротив, выбрасывает ошибку при добавлении бонусов, что
нарушает принцип LSP, так как ломает существующий контракт метода базового класса.

#### Правильная реализация

Для `BannedUser` метод добавления бонусов должен, например, просто вуедомлять о невозможности болавления бонусов,
сохраняя общий интерфейс и поведение.

Таким образом, в любых местах кода, где используется базовый класс, его наследники должны интегрироваться без нарушения
логики.

### Упражнение - Оплата в рассрочку

В этом упражнении разрабатывается систма платежей, соблюдая принцип подстановки Барбары Лисков. Создается три класса:

1. **Payment**: базовый класс, содержащий метод `pay()`, который списывает всю сумму `amount` и возвращает ее.
2. **Bonus Payment**: наследник `Payment`, применяется при наличии бонусов. Метод `pay()` переопределяется для учета
   бонусов, и возвращает сумму `amount`, уменьшенную на бонусы. Чтобы соблюсти принцип подстановки, задаются начальные
   значения бонусов, которые по умолчанию равны нулю.
3. **Installment Payment**: также наследник `Payment`, реализующий систему рассрочки. Метод `pay()` делит общую сумму
   на заданное количество частей и возвращает часть, которая списывается сразу.

Важно, чтобы метод `pay()` возвращал текущую сумму для списания, а не подтверждение полного платежа. Это необходимо для
соблюдения принципа Барбары Лисков: произвольный объект `Payment` должен быть заменяем объектом `BonusPayment` или
`InstallmentPayment` без изменения поведения программы.

Таким образом, система создана гибкой и расширяемой, что позволяет без нарушения принципов ООП добавлять новые типы
платежей и сохранять корректное их использование в коде.

### Interface Segregation Principle

В этой лекции рассматривается принцип разделения интерфейса (Interface Segregation Principle) в программировании,
который является частью SOLID-принципов.

#### Основная идея

Программисты не должны заставлять классы имплементировать методы, которые им не требуются. Интерфейсы должны быть
узкими и специализированными, чтобы избежать ненужной функциональности.

#### Пример нарушения принципа

Создан класс принтера с методами `print_doc()`, `scan_doc()`, `fax_doc()`. Старый принтер может только печатать, но
наследуясь от общего интерфейса, вынужден включать методы `scan_doc()` и `fax_doc()`, хотя и не реализует их (и даже
выыдает ошибки).

#### Решение

Разделить интерфейсы на более атомарные:

- `Printable` с методом `print_doc()`;
- `Scannable` с методом `scan_doc()`;
- `Faxable` с методом `fax_doc()`.

Сорвеменный принтер раелизует все три интерфейса (`Printable`, `Scannable`, `Faxable`) и методы. Старый притнер
раализует только `Printable` и метод `print_doc()`.

#### Вывод

Создавая узкие интерфейсы, можно избежать навязывания ненужной функциональности и упрощать архитектуру программ. Это
облегчает переиспользование кода и делает систему более гибкой.

### Упражнение - Методы оплат

В этом упражнении обсуждается применение принципа разделения интерфейсов на практике в контексте процессора платежей.

**Проблема**. Изначально у нас есть класс, котрый нарушает принцип разделения ответственности, так как содержит слишком
много несвязанных методов: `pay()`, `refund()`, токенизация карты, проверка баланса.

**Приныип разделения интерфейсов**. Необходимо ограничивать интерфейсы, чтобы классы не имплементировали методы,
которые им не нужны.

#### Решение

Создать астрактные классы, которые описывают отдельные аспекты платежной системы.

- `Payable` с абстрактными методами платежей `pay()` и `refund()`.
- `Tokenizable` с абстрактным методом токинизации карты `tokenize_card()`.
- `BalanceCheckable` с абстрактным методом баланса карты `check_balance()`.

#### Реализация

**`MasterCard`** реализует `Payable` и `Tokenizable`, включающие `pay()`, `refund()` и `tokenize_card()`.

**`Kiwi`** реализует только `Payable` (методы `pay()` и `refund()`).

**`PayPal`** реализует `Payable` и `BalanceCheckable`, то есть `pay()`, `refund()` и `check_balance()`.

#### Вывод

Разделение большого интерфейса на специализированные облегчает дальнейшую работу с классами и их реализацию для разных
способов оплаты.

### Dependency Inversion Principle

Модули верхних уровней не должны напямую зависеть от модулей нижних уравней. Оба типа модулей долждны зависеть от
абстраций, а не абстракции от деталей.

#### Пример

Есть сервис пользователя и логгер, который логирует информацию. Нарушение принципа DIP происходит, когда сервис
напрямую зависит от конкретного логгера (например, файл логгер).

#### Проблемы

При изменении способа логирования (например, с файла на консоль) нужно менять код в каждом месте, где используется
конкретный логгер. Это приводит к трудоемкости и возможности ошибок.

#### Решение

Ввести асбтракцию: создать абстрактный класс `Logger` с методом `log()`. Реализовать конкретные логгеры (`FileLogger`,
`ConsoleLogger`), наследующие абстарактный `Logger`. Серсис пользователя должен зависеть от абстракции `Logger`, а не
от конкретной реализации.

#### Преимущества

Гибкость: можно легко менять реализацию логгера без изменения кода сервиса. Легкость в расширении: добавление новых
типов логгеров не требует изменения существующего кода.

Использование принципа DIP позволяет сделать приложение более гибким и устойчивым к изменениям, поддерживая зависимость
от абстракций вместо конкретных реализаций.

### Упражнение - Оповещения о низком остатке

В данной лекции обсуждается применение принципа инверсии зависимости (Dependency Inversion Principle) на примере
разворачивания сервиса мониторинга остатков товаров на складе (`LowStockService`).

#### Задача

Создать сервис Low Stock Service с методом `run()`. Метод проверяет остатки в репозитории (`InMemoryStockRepository`)

#### Реализация принципа

#### Запуск и тестирование

Приложение создается и запускается с конкретными реализациями репозитория и нотификатора. Корректность работы

#### Преимущества

Код легко адаптируется к новым требованиям: можно поменять механизм уведомления или структуру хранения товаров, не

Заключение: использование принципа инверсии зависимости позволяет добиться гибкости и устойчивости приложений к

## Раздел 7. Работа под капотом

### Архитектура Python

В данном разделе будет углубление в архитектуру Python и его реализацию, известную как CPython.

#### Python и CPython

Python - это язык программирования, который здесь изучается. CPython - основная реализация Python на языке C, которая
здесь используется. Существуют и другие реализации, например, Rust Python. CPython - это движок, который позволяет
испольнять Python-программы.

#### Компоненты CPython

- **Парсер** преобразует код в синтаксическое дерево.
- **Компилятор** переводит синтасическое дерево в код объект и далее в байт-код, который будет интерпретироваться.
- **Виртуальная машина (VM)** исполняет байт-код.
- **Объектная модель** определяет все типы данных, например, int, list.
- **Менеджер памяти и Garbage Collector** управляют памятью и устраняют циклические ссылки между объектами.
- **Дополнительный API** для расширений на C.

#### Важность понимания внутренностей Python

Знание внутренней работы Python помогает в понимании особенностей языка и его производителшьности. Это ключевой шаг для
любого разработчика.

В последующих лекциях будет более подробно рассмотрен каждый из компонентов CPython и их роль.

### Pipeline компиляции

В этой лекции рассмотрен процесс выполнения Python-кода, начиная с запуска файла. Под капотом Python проходит через
пять стадий.

1. **Лексический анализ (токенизация)**. Код разбивается на минимальные единицы - токены, такие как переменные,
   операторы и числа.
2. **Синтаксический анализ**. Создается абстрактное синтаксическое дерево (AST), представляющее структуру кода. Для
   примера кода `x = 1 + 2`, дерево показывает, что переменной `x` присваивается результат сложения.
3. **Построение абстрактного синтаксического дерева**. Процесс превращает код в структуру, которую компилятору легко
   интерпретировать.
4. **Компиляция в код-обжект**. AST преобразуется в промежуточное предстваление - код-обжект.
5. **Исполнение байт-кода на виртуальной машине CPython**. Код-обжект преобразуется в байт-код, который исполняется,
   обеспечивая получение результата, например, `x = 3` для `x = 1 + 2`.

Примечания о PyCache: PyCache хранит скомпилированные версии файлов в формате `.pyc`, что ускоряет повторные запуски,
так как процесс компиляции не повторяется, если модуль не изменился. Python является компилируемым языком: он переводит
высокоуровневый код в байт-код, который затем исполняется.

### Eval Loop

В этой лекции рабзирается, как исполняется байт-код Python с помощью eval loop.

**Eval Loop** - это бесконечный цикл, который построчно исполняет инструкции байт-кода. Например, инструкция "загрузить
константу" или "выполнить сложение" разбирается и выполняется соответствующее действие.

**Стековая виртуальная машина**. Python использует стек для исполнения команд. Коаждая инструкция может добавлять или
удалять элементы стека. Это облегчает выполнение, но усложняет многопоточность.

**Пример выполнения**. Код `x = 1 + 2` превращается в инструкции: загрузить константу 1, загрузить константу 2,
выполнить сложение, сохранить результат. Эти операции изменяют содержимое стека, добавляя или извлекая данные.

**Стек-фреймы**. Для работы с вложенными функциями и итераторами используются стек-фреймы. Они представляют собой
отдельные области, которые помогают управлять контекстом функций. При вызове функции текущий стек замораживается, и
создается новый, вложенный стек-фрейм. После завершения функций стек-фреймы исчезают, возвращая результат в основной
стек.

**Визуализация с помощью библитореки dis**. Можно использовать библиотеку для дисассемблирования байт-кода Pytnon,
чтобы увидеть, как инструкции соотносятся со стеком и стек-фреймами.

**Отличие стека и многопоточности**. Стек безопасен и удобен для выполнения простых последовательных операций, но при
многопоточности возникают трудности, требующие специальных решений.

Понимание этих конецепций помогает оценить, как Python эффективно управляет выполнением кода и как это может влиять на
производительность, особенно в контексте сложных программ.

### Модель объектов

В этой лекции рассматривается, как Python работает под капотом, используя реализацию CPython.

#### Объекты в Python

В Ptyhon все является объектами, включая простые числа и классы. Все объекты базируются на `PyObject`, который написан
на C.

#### Основные компоненты PyObject

**Счетчик ссылок** позволяет отслеживать, сколько ссылок указывает на объект. Это важно для управления памятью и
удаления ненужных объектов. **Указатель на тип** указывает на `PyTypeObject`, который содержит функции для работы с
объектами.

#### PyTypeJbject

Содержит функции для установки и получения атрибутов, конструирования объектов и деструкторов. Например, когда пишется
`x + y`, выполняется вызов встроенных методов для сложения.

### Slots

В этой лекции рассматривается разница между использованием обычного словаря атрибутов (**dict**) в классе и слотов
(**slots**) для более эффективного использования памяти.

#### Объекты и память

В Python классы обычно использубт **dict**, который хранит атрибуты объекта в виде хэш-таблицы, что дает гибкость, но
требует больше памяти. Пример: при создании класса с двумя атрибутами `x` и `y`, использоваине **dict** занимает
значительно больше памяти, чем сами атрибуты.

#### Использование slots

Слоты позволяют фиксировать список атрибутов, исключая создание **dict** и снижая потребление памяти. При использовании
слотов нельзя добавлять новые атрибуты, не указанные в **slots**. Пример: при задании слотов для `x` и `y`, объект
класса занимает меньше памяти, чем при использвании хэш-таблицы.

#### Practical Example

Два класса: один с **dict**, другой с **slots**. Оба содержат атрибуты `x` и `y`. Использование **slots** позволяет
уменьшить потребление памяти, что важно при создании множества однотипных объектов.

#### Особенности наследования с slots

При наследовании могут возникнуть сложности: обычное наследование создает **dict**, но использование специального
синтаксиса может предотвратить это. Важно учитывать особенности при наследовании классов со слотами, так как это может
повлиять на структуру класса и потреблении памяти.

#### Рекомендации

Использовать **slots**, когда нужно создать много однотипных объектов с фиксированными атрибутами. Если требуется
гибкость и возможность добавления новых атрибутов, лучше использовать **dict**. Подход к использованию **slots** должен
основываться на необходимости оптимизации потребления памяти для множества объектов.

### Память и сборка мусора

На этом уроке рассматривается работа с памятью и сборка мусора в Python.

#### Ссылки и память

Каждый объект в Python имеет счетчик ссылок, показывающий количество активных ссылока на него. Объект удаляется, когда
счетчик ссылок падает дол нуля. Проблемы возникают с циклическими зависимостями, когда объекты ссылаются друг на друга,
образуя замкнутый круг.

#### Garbage Colector

В Python используется сборщик мусора, рботающий по модели поколений. Объекты распределяются по трем поколениям:

- **Поколение 0**. Недавно созданные объекты, проверяются чаще всего.
- **Поколение 1**. Пережившие несколько проверок объекты, проверяются реже.
- **Поколение 2**. Долгоживущие объекты, проверяются еще реже.

Garbage Collector оптимизирует проверки, избегая частых операций с долгоживущими объектами.

#### Практика работы с памятью

Нужно использовать `sys.getrefcount()`, чтобы получить количество ссылок на объект. Оператор `del` удаляет ссылки на
объект, но не сам объект, пока есть другие ссылки. Круговые зависимости можно выявить и управлять ими с помощью пакета
`gc`.

#### Управление Garbage Collector

Сборщик мусора запускается автоматически, но его можно запустить вручную с помощью `gc.collect()`. Метод
`gc.get_stats()` дает статистику по поколениям. В ручном управлении обычно нет необходимости, так как сборщик мусора
оптимизирован для автоматической работы.

**Итог**: понимание этих механизмов помогает эффективно управлять памятью в Python, избегая утечек и отпимизируя
производительность.

### Исключения под капотом

В этой лекции разбирается, как работают исключения в Python под капотом, в частности, в контексте стек-фреймов.

#### Стек-фреймы и исключения

Каждый стек-фрейм содержит код программы и блоки обработки исключений (try/except, try/filally). PySpaceExceptionObject
хранит детали исключений, такие как трейсбэк и причина.

#### Поиск и обработка исключений

При возникновении исключения, ищется обработчик в текущем фрейме. Если обработчик найден, исключение обрабатывается
локально. Если нет, текущий фрейм уничтожается, и поиск перенаправляется на предыдущий фрейм.

#### Если исключение не обработано

Если никто из фреймов не содержит обработчик, программа выводит информацию об ошибке и завершает работу.

#### Связь исключений

Если ранее возникнувшая ошибка приводит к новой, вся цепочка исключений сохраняется и может быть проанализирована
позднее.

#### Итог

Понимание работы исключений и стек-фреймов помогает более эффективно отлаживать и предсказывать поведение программ.

Это знание об устройстве работы с исключениями под капотом дает более глубокое понимание программирования на Python и
помогает в сложных ситуациях с обработкой ошибок.

## Раздел 8. Generics и typing

### Обобщения

#### Что такое дженерики

Обобщенные типы позволяют создавать функции и классы, которые могут работать с различными типами данных, обеспечивая
при этом правильную типизацию.

#### Пример без дженериков

Рассмотрена функция `first_item()`, которая принимает список и возвращает первый элемент. Функция корректно работает с
различными типами (строки, числа), но сигнатура не предоставляет информацию о типах элементов списка, что делает код
менее понятным.

#### Проблема типизации

Без дженериков сложно задать сигнатуру, которая указывает тип элементов в списке. Без них фнкция принимает и возвращает
`Unknown`, что не информативно.

#### Использование дженериков

С помощью `TypeVar` из модуля `typing` можно задавать обобщенный тип `T`. Принимается список типа `T` и возвращается
элемент типа `T`.

#### Преимущества дженериков

Дженерики позволяют точно определить, какие типы данных принимает и возвращает функция. Улучшают читаемость и
поддерживаемость кода. Полезны для функций, работающих с разными типами данных.

#### Типичное применение

Используется в случаях, когда функция или класс должны работать с более чем одним типом данных. Пример: стандартный тип
`list()` в Python - это тоже дженерик.

Дженерики делают функции более универсальными и помогают избежать ошибок, связанных с типизацией, что особенно важно в
крупных проектах.

### Callable

#### Изучение сложных примеров с Generics

Использование нескольких generics для типизации функции, работающей со списками и их преобразованием.

#### Функция process_items

Предназначена для обработки списков (`items`) с применением функции-трансформера (`transformer()`) к каждому элементу.
Возвращает новый список, где каждый элемент трансформирован.

#### Пример функции to_upper()

Преобразует строку в верхний регистр. Может быть передана как трансформер в `process_items()`.

#### Проблема типизации

Необходимо задать понятные типы для функции, чтобы она не принимала неясные параметры и не возвращала "неопределенные"
списки.

#### Использование Generics

Вводятся generics `T` и `R` для входного и выходного типов соответственно. Позволяет функции работать с различными
типами данных (например, строками и числами).

#### Тип Callable

Описывает функцию, принимающую определенные аргументы и возвращающую значения. В данном случае `Callable` используется
для типизации функции-трансформера внутри `process_items()`.

#### Преимущества типизации

Существенно повышает понятность сигнатуры функции. Упрощает поддержку и расширение кода за счет явного обозначения
входных и выходных данных.

#### Итог

Благодаря дженерикам и Callable, можно типизировать функции, работая с разнообразными данными, обеспечивая четкое
понимание процесса и ожидаемых результатов.

### Упражнение - Работа с tuple

В этом упражнении рассмотрена работа с дженериками и созданы несколько функций, работающих с парами элементов.

#### Функция make_pair()

Задача: принять два значения и создать из них кортеж (tuple). Использовать дженерики `T` и `R` для орбозначения типов
входных значений и кортежа.

#### Функция get_first()

Задача: извлечь первый эелемент из переданного кортежа. Принимает кортеж (tuple) типов `T` и `R`, возвращает тип `T`.

#### Функция get_second()

Задача: извлечь второй элемент из переданного кортежа. Принимает кортеж (tuple) типов `T` и `R`, возвращает тип `R`.

#### Функция swap_pairs()

Задача: поменять местами элементы в переданном кортеже. Принимает кортеж (tuple) типов `T` и `R`, возвращает кортеж
(tuple) типов `R` и `T`.

### Optional

В этом уроке рассмотрено, как использовать тип `Optional` из библиотеки `Typing` в Python и как это может быть полезно
при разработке с использованием функций и классов.

#### Что такое Optional

`Optional` обозначает, что функция может вернуть значение указанного типа или `None`. Это облегчает работу с функциями,
возвращающими потеныиально отсутствующие значения.

#### Пример использования

Допустим, есть класс `User` с полями `id`, `name` и `email`. Пишется функция `get_user_by_id`, которая получает
идентификатор пользователя `user_id` и возвращает объект пользователя, если он найден, или `None` если его нет.

#### Импорт и испольование Optional

Импортируем `Optional` из библиотеки `Typing`. Функция будет возвращать тип `Optional[User]`. Это значит, что функция
может вернуть либо объект `User`, либо `None`.

#### Как работает функция

Цикл перебирает пользователей и сравнивает `user.id` с `user_id`. Если совпадает, возвращам пользователя. Если нет
совпадений, возвращаем `None`.

#### Преимущества использования Optional

Улучшает читаемость кода. Позволяет явно указать возможность `None` в качестве возвращаемого значения. Позволяет
корректно типизировать функции.

### Упражнение - Safe методы

В этой лекции рассматривается, как использовать Optional и Generic для создания трех функций в Pytnon.

1. **save_get()**
   - Цель: получение значения из списка по индексу с безопасной обработкой.
   - Описание: функция пнринимает список (`list[T]`) и индекс (`int`).
   - Возврат: возвращает элемент списка (`T`) или `None`, если индекс за пределами списка.
   - Используемые методы: `Optional[T]` для возврата либо значения, либо `None`.
2. **map_optional()**
   - Цель: применение функции к значению, если оно не `None`.
   - Описание: функция принимает значение (`Optional[T]`) и трансформер-функцию (`Callable[[T], R]`).
   - Возврат: возвращает преобразованное значение (`Optional[R]`), либо `None`, если исходное значение было `None`.
   - Используемые методы: `Optional`, `Callable`, два дженерика для типизации входного и выходного типов.
3. **or_else()**
   - Цель: возврат значения, если оно не `None`, или дефолтного значения в противном случае.
   - Описание: функция принимает значение (`Optional[T]`) и дефолтное значение (`T`).
   - Возврат: возвращает значение (`T`), либо дефолтное, если основное значение `None`.

В процессе реализации используются пнятия дженериков (`TypeVar`), чтобы описать типизацию функций более подробно и
гибко, применяя их к различным параметрам и возвратам. Также демонтсрируется применение `Callable` для передачи функций
в качестве параметров.

### Generic Class

#### Проблема

Создание классов для хранения данных разных типов (например, `int`, `str`) ведет к дублированию кода. Для каждого типа
данных ребуется отдельный класс (например `IntBox`, `StrBox`) с одинаковым кодом.

#### Решение с дженериками

Дженерики позволяют создавать классы, которые могут работать с разными типами данных без дублирования кода.

#### Применение

1. **Импорт зависиомостей**
   - Подключается `Generic` и `TypeVar` из модуля `typing`.
2. **Обявление дженерика**
   - Создается тип-дженерик `T` с помощью `TypeVar`.
3. **Создание дженерик-класса**
   - Создается класс `Box`, который наследуется от `Generic[T]`.
   - Определяется переменная `value` типа `T`.
   - Реализуется метод `get()`, который возвращает значение `value` типа `T`.

#### Преимущества

Позволяет использовать один класс для работы с разными типами данных. Избегает дублирование кода и улучшает его
поддержку.

#### Вывод

Дженерики в классах делают код более обобщенным и удобным для работы с различными типами данных, что пригодится при
создании сложных приложений.

### Упражнение - Репозиторий

#### Цель

Создать универсальный репозиторий, который может работать с любыми типами данных.

#### Определение репозитория

Репозиторий - это класс, который хранит объекты произвольных типов в списке и предоставляет методы для добавления и
извлечения элементов.

#### Шаги реализации

1. **Импорт библиотек**
   - Импортировать классы `Generic` и `TypeVar` из модуля `typing`.
2. **Создание TypeVar**
   - Определить `TypeVar` как `T`, чтобы обозначить произвольный тип.
3. **Создание класса `Repository`**
   - Класс наследуется от `Generic[T]`.
   - Использует внутренний список `items` для хранения объектов типа `T`.
4. **Реализация методов**
   - Метод `add()` (добавление элементов): принимает элемент типа `T`; добавляет элемент в список `items`.
   - Метод `get_by_index()` (получение элемента по индексу): принимает индекс и возвращает элемент или `None`, если
     индекс неверный; использует `Optional[T]` в качестве возвращаемого типа.
   - Метод `get_all()` (получение всех элементов): возвращает список всех элементов типа `T`.

#### Использование репозитория

Создание объектов репозитория: можно создать пустой репозиторий или задать тип `T` с помощью аннотации (например, `int`
или `str`). Пример использования: добавить элементы в репозиторий; извлечь элементы по индексу и отобразить результаты.

#### Тестирование

Проверка корректности работы через вывод элементов в терминале. Обработка ошибок, таких как `list index out of range`.

Данный подход позволяет создавать универсальные хранилища для различных типов данных, что делает код более гибким и
переиспользуемым.

### Ограничения типов

Дженерики позволяют обрабатывать разные типы данных через универсальные функции и классы. Однако из-за их гибкости
возникают ограничения, такие как невозможность использования операторов сравнения и арифметических операций для
произвольных типов данных.

#### Проблема дженериков

Дженерики могут принимать любой тип данных. Невозможно гарантировать поддержку операторов (например, сравнения или
сложения) для всех типов данных.

#### Пример проблемы

Метод `max(a, b)` - сравнение невозможно без определения типов.

Метод `add(a, b)` - сложение невозможно для неизвестных типов.

#### Ограничение дженериков

Чтобы задать ограничение дженерикам (например, разрешать только `int` и `float`), используется `TypeVar` с указанием
допустимых типов. Это позволяет использовать операции, поддерживаемые только этими типами.

#### Практика именования дженериков

Рекомендуется давать наименования, описывающие предназначение. Например, назвать дженерик `Number`, если он принимает
только числовые типы (`int`, `float`).

#### Применение в ООП

Ограничения джерериков применимы также к классам.

### Generic bound

В этой лекции обсуждалась работа с ограничениями типов при помощи `TypeVar` и протоколов в Python.

#### Задание ограничений

Объяснялось, как с помощью `TypeVar` и параметра `bound` можно ограничивать дженерики только определенными классами.
Пример: создание класса `TaskRunner`, который принимает задачи, имеющие метод `run()`.

#### Создание класса TaskRunner

`TaskRunner` запускает задачи, находящиеся в списке `tasks`. Задачи могут быть разными (например, отправка email или
сохранение пользователя).

#### Использование протоколов

Протокол позволяет определить контракт, указывая, что класс должен иметь определенные методы (например, метод `run()`),
чтобы его можно было использовать.

#### Применение Generic

Generic используется для создания универсального класса `TaskRunner`, принимающего задачи, соответствующие заданному
протоколу. Используется `TypeVar` с ограничением `bound`, чтобы убедиться, что задачи соответствуют протоколу
`Runnable`.

#### Практическое применение

Ограничивая типы, можно использовать любой класс, имеющий метод `run()`. IDE помощьник будет подсказывать доступные
методы, обеспечивая безопасность и удобство при разработке.

Этот подход позволяет создавать безопаснвй и гибкий код, обеспечивающий, что только задачи с определенным набором
методов могут быть обработаны `TaskRunner`.

### Упражнение - Поиск по id

#### Определение классов

Создаем классы для пользователей, продуктов и заказов. У каждого класса есть атрибут `id` и специфические поля, такие
как `email` у пользователя или `title` у продукта.

#### Создание функции поиска get_by_id()

Функция принимает список элементов и искомый `id`. Возвращает элемент из списка с соответствующим `id` или `None`, если

#### Использование обобщенного программирования (Generics) и протоколов

Используется протокол `Identifiable`, который требует наличие `id` у класса. Создается обобщенный тип `T` с
ограничением (bound), что он должен быть `Identifiable`.

#### Импорт и применение

Импортируем необходимые модули, такие как `Optional` и `TypeVar`. Определяем функцию `get_by_id()` с испольованием
типов и ограничений. Функция проверяет наличие `id` и возвращает соответствующий элемент.

#### Проверка работы функции

Функцию можно использовать для поиска пользователя по `id` в списке. Если объект не соответствует протоколу
`Identifiable`, выдается ошибка.

Таким образом, используя дженерики и протоколы, создается безопасная и универсальная функция поиска, которая
предупреждает об ошибках на этапе компиляции.

### Union

Юнион типы в Python помогают работать с функциями, которые принимают или возвращают разные типы данных.

#### Задача юнион типов

Они позволяют функции возвращать разные типы данных, например, число или строку. Это удобно, когда результат вычисления
может быть не единственным типом.

#### Пример использования

Функция безопасного деления (`safe_div()`) может возвращать число при успешном делении или строку "Деление на 0" при
ошибке. Это реализуется с помощью юнион типа, указывающего на возможность возврата `float` или `str`.

#### Синтаксис юнион типов

Старый синтаксис требует импорта `Union` из модуля `typing` и используют запись `Union[float, str]`. Новый синтаксис,
начиная с Python 3.10, использует вертикальную черту: `float | str`.

#### Практические примеры

Функция `ensure_list()` преобразует переданное значение в список, будь то строка или список строк. Используется юнион
тип для описания принимаемого параметра.

#### Сужение типов (Type Narrowing)

Это механизм, который помогает уточнять тип переменной внутри блока кода, используя проверки, например `isinstance()`.

#### Дженерики и расширяемость

`ensure_list()` можно сделать универсальной с помощью генераторов типизации (`TypeVar('T')`), что позволяет функции
работать с любой переданной типизацией.

#### Преимущества

Юнион типы и дженерики дают большую гибкость и уверенность в определении типов, что позволяет улучшить читаемость и
надежность кода.

Итак, юнион типы эффективны, когда функции работают с разными типами данных, и вместе с дженериками они расширяют
возможности типизации в Python.

### TypeGuard

TypeGuard - это инструмент в Python, позволяющий сузить типы переменных и более точно работать с ними внутри функций.
Это полезно при работе с переменными, имеющими тип юнион.

#### Пример использования

Есть функция `f()`, принимающая список, который является юнионом двух типов: `list[int]` и `list[str]`. Необходимо
бзопасно использовать методы, специфичные для этих типов. Без использования TypeGuard нельзя определить, какие методы
доступны, и, например, метод `capitalize()` не сработает для типа `int`.

#### Определение TypeGuard

TypeGuard - это функция, которая помогает определить и сузить тип переменной. Импортируется из модуля `typing`.

#### Пример создания TypeGuard

Создается функция `is_int_list(x)`, чтобы проверить, что список состоит только из элементов типа `int`. Возвращаемый
тип функции - `TypeGuard[list[int]]`.

#### Применение TypeGuard

Используется функция `is_int_list(xs)`, чтобы проверить, является ли `xs` списком из `int`. При успешной проверке
дальше работаем с `xs` как со списком `int`, а значит, доступны все методы для `int`.

#### Ограничения TypeGuard

Если выполнить проверку в `else`, необходимо явно определить, что это список строк с помощью аналогичного TypeGuard для
строк.

## Раздел 9. Асинхронное программирование

### Зачем асинхронность

#### Зачем нужна асинхронность

**Эффективность работы программы**. Позволяет выполнять другие задачи, пока одна задача ожидает завершения (например,
сетевой запрос или доступ к базе данных).  
**Минимизация задержек**. Улучшает производительность сетевых операций и I/O операций.  
**Оптимизация ресурсов**. Предотвращает создание множества потоков, что може быть дорого по ресурсам.

#### Основные концепции

**Асинхронность vs. Параллелизм**. Асинхронность - переключение между задачами в одном потоке, не требует
многопоточности.  
**Асинхронность vs. Многопоточность**. Асинхронность лучше подходит для I/O операций, тогда как многопоточность может
быть полезна для задач, требующих параллельной работы с CPU.  
**Корутины**. Легкие процессы для управления асинхронными задачами без необходимости создавать новые потоки.

#### Необходимые понятия и технологии

**asyncio** - библиотека для работы с асинхронностью в Python.  
**async/await** - ключевые слова для работы с асинхронными функциями.  
**EventLoop** - цикл событий, управляющий выполнением асинхронных задач.

#### Ограничения асинхронности

Не подходит для тяжелых вычислений; такие задачи могут заблокировать поток. В таких случаях лучше использовать
многопоточность или даже отдельные процессы.

#### Практическое применение

Подходит для разработки HTTP-сервисов, где важно обрабатывать несколько запросов одновременно. Асинхронные операции
сводят к минимуму задержки, позволяя эффективнее использовать текущие потоки при I/O операциях.

Цель: освоить работу с асинхронностью через asyncio и понять, как эффективно управлять задачами с помощью EventLoop. В
дальнейших лекциях более подробно разберем async-await и работу EventLoop.

### async await

#### Определение корутины

Корутина - это функция с приставкой `async`, которая возвращает объект корутины, вместо обычного значения, например
строки. Для использования корутины требуется использовать `await` для временной приостановки ее выполнения.

#### Разница между корутинами и обычнвми функциями

Корутины не болкируют поток выполнения, что позволяет процессору обрабатывать другие конкурентные задачи. В обычных
функциях `await` не используется.

#### Зпуск корутин и Event Loop

Для запуска корутин используется `asyncio.run()`, что запускает основной Event Loop - это как точка входа для
отслеживания и управления асинхронными задачами. Внутри Event Loop для запуска спуцифических корутин используется
`asyncio.create_task()`.

#### Создание простой корутины

Пример: фнукция `main()`, которая выводит "Привет". Запуск через `asyncio.ru(main()).

### Event Loop

Event Loop - это ключевая часть asyncio, отвечающая за управление асинхронными задачами.

#### Создание и задачи Event Loop

Создается при запуске asyncio. Задачи: запуск и приостановка корутин, восстановление и выполнения после завершения
операции, управление таймерами, вводом-выводом, callback'ами и планирование задач в одном потоке.

#### Преимущества работы в одом потоке

Избегает сложности и затрат на управление многопоточностью. Эффективное использование ресрсов, учитывая ограничения
процессора по числу параллельных потоков.

#### Структура Event Loop

Две очереди: готовых и ожидающих задач. Готовые задачи - это те, которые можно немедленно выполнить. При достижении
точки ожидания, задачи перемещаются в очередь ожидания.

#### Механизм работы

Event Loop циклично выполняет задачи из очереди готовых задач. При достижении await, задача помещается в очередь
ожидания, чтобы дождаться завершения операции (например, сетевого запроса). После завершения условия ожидания, задача
возвращается в очередь готовых задач и выполняется до завершения.

#### Эффективность

Event Loop позволяет выполнять одновременно несколько асинхронных вызовов, максимально используя возможности CPU.
Избегает блокировок и простаивания процессора, продолжая выполнять другие задачи, пока одна ждет завершения своей
операции.

#### Завершение работы

Event Loop завершается, когда все задачи выполнены и приложению больше нечего обрабтывать.

Таким образом, Event Loop обеспечивает эффективную и упрощенную модель выполнения асинхронных задач, гарантироуя
максимальную производительность и использование ресурсов CPU.

### wait и wait_for

На этом уроке обсуждается работа с асинхронными задачами в Python с использованием библиотеки `asyncio`, а именно
различия в смешании и управлении выполненнием через asyncio Wait и Gather.

#### asyncio wait vs. gather

**Gather**. Удобен для запуска параллельно и ожидания завершения всех задач. Аргументы передаются через распаковку.  
**Wait**. Более гибкий инструмент. Принимает список задач (tasks) напрмую и позволяет управлять поведением выполнения
(например, верунть первй завершившийся результат).

#### Работа с wait

Превращение корутины в задачи через `asyncio create_task()`. Метод `wait()` возвращает два списка: `done` (завершенные)
и `pending` (в работе). Можно указать поведение возврата через параметр `return_when`: например, `FIRST_COMPLETED` для
возврата первого завершенного.

#### Примеры использования

Управление результатами из нескольких источников и выбор самого быстрого отклика. Метод `wait_for()` с тайм-аутом для
предотвращиния бесконечного ожидания при выполнении задач.

#### Ошибка и обработка исключений

Важно обрабатывать возможные ошибки, особенно в контексте асинхронных функций. Использование тайм-аута предотвращает
заморозку при недоступности ресурса.

Это объяснение подчеркивает гибкость и преимущества инструмента asyncio wait в контроле над выполнением асинхронных
задач.

### Обработка ошибок

#### Работа с ошибками в асинхронном коде

##### Создание задач и обработка ошибок

Импортирование `asyncio` и создание задачи с помощью `asyncio.create_task()`. Использование try/exception для обработки
исключений, таких как _ValueError_.

##### Запуск задач

Задача начинается сразу после создания. Для получения результата используестя `await` до task. Если задача создается,
но ее результат не используется (нет `await`), ошибка может быть проигнорирована.

##### Callback для необработанных задач

Если нет ожидания (не `await`) задачи, нужно использовать `add_done_callback()` для обработки результатов через
callback. Callback позволяет обработать исключение через функцию, вызываемоую по завершении задачи.

##### Использование gather() для нескольких задач

Используется `asycnio.gather()` для запуска нескольких задач и сбора их результатов. Если одна из задач вызывает
исключение, gather также завершает работу с исключением, если параметр `return_eceptions=False` (по умолчанию).
Установить `return_eceptions=True`, чтобы собрать результаты задач, включая исключения.

##### Обработка различных ошибок

Обработка исключений, хараткерных для `asyncio`, таких как _asyncio.TimeoutError_, при использовании функции
`wait_for()`.

##### Рекомендации

Всегда обрабатывать исключения через try/except. Если задача запускается, но результат не используется - добавить
обработку с помощью callback. Для gather использовать `retuen_exeptions=True`, если подходит частичное выполнение
задач.

Таким образом, обработка ошибок в асинхронном программировании важна для устойчивой работы приложений.

### shield

В этом уроке обсуждается использование `asyncio.shield()` для защиты задач в асинхронном программировании на Python с
использованием библиотеки `asyncio`.

#### Проблема отмены задач

Допустим, есть главная задача (`job()`), которая выполняет сохранение данных в базе данных. Если задача (`job()`)
отменяется до завершения сохранения, это может привести к неполной транзакции.

#### Решение с asyncio.shield()

Для предотвращения неожиданного завершения дочерней задачи (напримпр, сохранения), используется `asyncio.shield()`.
Этот механизм защищает задачу от отмнеы, если отменяется **только** ее родитель. Задача продолжает выполнение до
завершения независимо от состояния родительской задачи.

#### Практическое применение

`asyncio.shield()` полезен не только для защиты транзакций в базах данных, но и для обеспечения завершения важных
процессов, таких как освобождение ресурсов. Важно для поддержания консистентности данных и выполнения очистки после
ошибок.

#### Ограничения

`asyncio.shield()` защищает только от отмены радительской задачи, но не полность изолирует от отмены напрямую.

Использование `asyncio.shield()` рекомендуется в ситуациях, где необходимо гарантировать завершение важной операции
даже при отмене родительской задачи.

### Task vs Coroutine

В этой лекции обсуждаются различия между задачами (tasks) и корутинами (coroutines) в контектсте работы с асинхронными
операциями в Python, используя `asyncio`.

#### Корутина vs Задача: основные определения

Корутина - это план выполнения, который не может самозапускаться; требует `await` для исполнения. Задача - это объект,
который запускается автоматически при создании (через `asyncio.create_task()`) и может выполняться без `await`.

#### Использование await

Для выполнения корутины всегда необходим `await`. Без него выполнение не произойдет. Задачи могут выполняться без
`await`. Напримпр, они будут выполняться независимо после создания.

#### Отмена и исключения

Задачи могут быть отменены (`cancel`) и могут обрабатывать исключения отмены. Корутины не могут быть отменены напрямую
и не могут обрабатывать исключения отмены.

#### Выполнение и обработка результатов

Как задачи, так и корутины могут возвращать результаты. Результаты корутин получаются через `await`, результаты задач
также можно получить, но они выполняются сразу после создания.

#### Когда использовать

Простые асинхронные действиия (например, `sleep()`) можно выполнять с корутинами. Для параллельного выполнения
нескольких операций лучше использовать задачи. Они позволяют более эффективно управлять несколькими задачами
одновременно.

#### Future

`Future` - это объект, который описывает состояние выполнения (готово или нет) и содержит итоговый результат. `Future`
является базовым элементом, от котоого наследуются задачи, обеспечивая автоматическое выполнение и возвращение
результатов.

Рекомендация заключается в приоритете использования задач для большинства операций, чтобы обеспечить параллельность и
контроль выполнения.

### Упражнение - Retry Coroutine

Лекция посвящена созданию асинхронной функции с повторными попытками выполнения.

**Задача**. Создать асинхронную корутину, которая будет запускать нестабильную корутину `unstable()`. Если выполнение
завершилось ошибкой, функцию следует повторять до заданного лимита попыток.

**Определение корутины**. Название корутины - `run_with_retry()`. Она будет принимать функцию и количество попыток (по
умолчанию - 3).

#### Цикл попыток

Используется цикл `for attempt in range(1, max_retries + 1)`. Каждая попытка создает task для корутины и ожидает его
завершения.

#### Обработка результатов и исключений

Если задача выполнена успешно, возвращается рузультат. При возникновении исключения (общий `Exception`) выводится
сообщение с количеством попыток. Если исчерпаны все попытки, выводится сообщение об исчерпании попыток.

**Асинхронная задержка**. Дорбавляется `asyncio.sleep(0.5)` для имитации ожидания.

**Вызов функции**. Запускается `run_with_retry()` с переданной корутиной и фиксированным числом попыток.

**Ошибка использования корутин**. Если передать уже вызванную корутину (`result = await run_with_retry(unstable())`),
возникает ошибка "cannot reuse already awaited coroutine". Нужно передавать непосредственную ссылку на функцию
(`result = await run_with_retry(unstable)`).

**Практическая проверка**. Функция тестируется на успешное выполнение после случайного числа попыток.

Лекция демонстрирует важность правильного обращения с корутинами, обработки исключений и стратегии повторных попыток,
что критично в асинхронном программировании.

Установка зависимостей без виртуального окружения приводит к их установке в глобальную облась, что может вызваь

#### Деактивация окружения

Команда `deactivate` возвращает на глобальное использование Python.

#### Рекомендации

### pip

Для управления зависимостями в проекте на Python используется менеджер пакетов pip.

#### Установка пакетов

Устанавливаются зависимости с помощью команды _pip install package-name_. Например `pip install requests`. Эта
команда автоматически устанавливает и зависимости самого пакета.

#### Установка конкретной версии

Чтобы установить определенную верию пакета, используется команда _pip install package-name==desired-version_.
Например, `pip install requests==2.25`.

#### Просмотр установленных пакетов

Команда `pip list` используется для просмотра всех установленных пакетов и их версий. Чтобы увидеть устаревшие пакеты,
необходимо выполнить команду `pip list --outdated`.

#### Обновление пакетов

Обновляются пакеты с помощью команды _pip install --upgrabe package-name_. Например,
`pip install --upgrade requests`.

#### Фиксация зависимостей

С помощью команды `pip freeze > requirements.txt` создается текстовый файл _requirements.txt_, содержащий текущие
зависимости. Этот файл важен для совместной работы в команде, чтобы каждый мог установить идентичные версии пакетов.

#### Установка из rquirements.txt

Зависимости из файла устанавливаются с помощью команды `pip install -r requrements.txt`.

#### Рекомендации

Обновляйте зависимости по одному, чтобы избежать потенциальных проблем с совметимостью. Используйте _pip_ для
управления версиями и зависимостями пакетов, чтобы проект оставался стабильным и повторяемым при развертывании.

Следуйте этим шагам для эффективного управления зависимостями в вашем Python проекте.

### project toml

На этом уроке рассказывается о современном подходе к управлению зависиостями Python-проектов с использованием файла

#### Что такое TOML и его преимущества

TOML - формат файлов для описания секций, ключей и значений проекта. Аналог файла _package.json_ в веб-разработке на
_Node.js_, являющимся "паспортом" проекта. Более удобное и современное решение по сравнению с _requirements.txt_,
которое позволяет избежать избыточных зависимостей и мусора.

#### Создание pyproject.toml

Значения маркируются двойными кавычками. Минимальные поля: имя проекта (например, NoteApp) и версия (например, 0.0.1).
Допольнительно можно указать описание проекта, минимальную требуемую версию Python и основные зависимости (например,
_requests_).

#### Опциональные зависимости

Определяются зависимости для разработки, например, PyTest для тестирования:

```
[project.optional-dependences]
dev = ["pytest"]
```

#### Управление зависиостями

Зависиости устанавливаются командой `pip install .`. Во время работы команды создаются артефакты, такие как _Build_ и
_egg-info_, которые подходят для продакшен сборки.

#### gitignore для артефактов

Содание _.gitignore_ для исключения из репозитория ненужных файлов (_Build_, _gee-info_).

#### Управление версиями зависимостей

Importance фиксации версий для стабильности проекта. Возможность фиксировать версии через _requirements.txt_, несмотря
на использование _pyproject.toml_. Альтернативные инструменты, такие как Poetry или Pipenv, для более эффективного
управления зависимостями.

Основная идея - _pyproject.toml_ предоставляет централизованную и современную структуру для описания и управления
зависиостями Python-проектов, которая улучшает контроль над версиями и структурой проекта.

### Генераторы

#### Что такое генератор:

Генератор — это особая функция, которая возвращает значения поэтапно, используя `yield`, а не один раз, как обычные
функции через `return`. Генераторы вычисляют значения только тогда, когда они запрашиваются, что позволяет экономить
память.

#### Создание и использование генератора:

Определяется функция с `yield`. При каждом вызове next() возвращается следующее значение до достижения конца
последовательности. Пример: создается генератор `gen_count_up_to(n)`, который считает до `n`, используя `yield`. Запуск
генератора происходит с помощью `next()`, вызывая следующий элемент. После окончания последовательности возникает
ошибка `StopIteration`.

#### Преимущества генераторов:

Экономия памяти: вместо хранения целого списка, значения вычисляются по мере необходимости. Можно использовать
генераторное выражение с круглыми скобками, вместо квадратных для списков, для создания генераторов.

#### Работа с другими итерируемыми объектами:

Генераторы могут быть созданы на основе других итерируемых сущностей, таких как строки.

#### Практическое применение:

Генераторы используются для создания более эффективных и памяти-экономных алгоритмов. Например, интерфейсы могут
формироваться поэтапно благодаря генераторам.

Таким образом, генераторы предоставляют мощный инструмент для управления памятью и упрощения алгоритмов, позволяя
вычислять и возвращать значения по требованию.

Устанавливается ruff с помощью Poetry в группу разработчиков (group dev), чтобы использовать только в процессе

Чтобы запустить линтинг, используется команда `ruff check`, которая проверяет код на типичные ошибки и неиспользованные
импорты. Для автоматического исправления ошибок добавляется параметр `--fix`.

### Bindings

В этой лекции описывается расширение функциональности приложения, добавляя возможность орбрабатывать нажатие клавиш, в

#### Добавление биндингов для клавиш

В `MainScreen` добавляются биндинги (`BINDINGS`) - это механизм, который позволяет задать действия для клавиш. Для
клавиши _Q_ задается действие _quit_ с названием _"Выход"_.

#### Добавление футера

Импортируется и добавляется футер из виджетов, чтобы отображать подсказки для пользователя в виде _"q Выход"_.

#### Реализация экшн

Чтобы сделать функционал полноценным, создаем метод с соглашением о наименовании экшенов: `action_quit()`. Если
действие в биндинге задано как _quit_,то называется _action_quit()_. Метод `action_quit()` описывает логику выхода из
приложения, например, посредством вызова `exit()`.

#### Проверка работы

На практике проверяется, что нажатие на _Q_ или клик по кнопке _"Выход"_ действительно завершает приложение. Это
достигается правильным сопоставлением биндинга и соответствующего экшена. Также этой клавише в разных раскладках и
регистрах (_Q, й, Й_) задается тоже действие (_quit_) без названия.

Эти шаги добавляют функциональность, которая улучшает навигацию и использование создаваемого приложения с помощью
клавиш.

### Паттерн репозитория

Итак, в данной лекции рассмотрен паттерн репозитория и его применение в приложении

#### Паттерн репозитория

Репозиторий служит посредником между внутренними сущностями приложения и внешним источником данных, такими как база
данных, файлы или API. Это позволяет инкапсулировать логику доступа к данным и предоставлять единое место для
взаимодействия с ними.

#### Преимущества использования репозитория

1. **Единая точка входа**. Доступ к данным осуществляется только через репозиторий, что упрощает управление и изменение
   исочника данных без влияния на основные бизнес-логики.
2. **Инкапсуляция логики доступа**. Реализация взаимодействия с конкретным источником данных сокрыта внутри
   репозитория.
3. **Гибкость и изменяемость**. Можно легко переключаться между разными способами хранения данных (файлы, API, БД),
   изменив реализацию репозитория.

#### Инверсия зависимостей

Реопзиторий является хорошим кандидатом для применения принципа инверсии зависимостей. Приложение должно зависеть от
абстракций, а не от конкретных реализаций репозитория.

#### Создание структуры

1. **Абстрактный класс репозитория**. Описываются базовые методы, такие как получение всех папок (`get_all_folders()`),
   создание (`create_folder()`), удаление папок (`delete_folder()`) и получение папки по пути (`get_folder_by_path()`).
2. **Конкретная реализация**. Реализуются методы абстарактного класса в конкретной реализации репозитория для работы с
   файлами.

#### Связывание элементов

Репозиторий связывает физические данные (например, файлы) с бизнес-сущностями приложения, обеспечивая преобразование
данных в формат, понятный для внутренного использования в приложении.

Эта структура позволяет легко адаптировать приложение к изменениям в хранении данных и делает код более организованным
и поддерживаемым.

### Упражнение - Удаление и создание

#### Создание директории

Используется метод `mkdir()` из `path` (`path.mkdir()`) для создания новой директории. Предварительно необходимо
передать путь, по которому нужно создать директорию. Важно провести проверки:

- убедиться, что путь существует и валиден;
- проверить, что имя директории корректно (например, не содержит запрещенных символов).

После проверок создается директория с параметрами `parents=True` и `exist_ok=False`, если директория уже существует.
Возвращается созанный путь или директория.

#### Удаление директории

Для удаления директории импортируется `shutil` и исползуется `shutil.rmtree()`. Надо взять путь директории, которую
планируется удалить. Производится проверка, чтобы не удалялся базовый путь (предупреждение удаления корневой
директории). Если все проверки пройдены, осуществляется удаление.

#### Метод _chek_path_

Общие проверки выносятся в отдельный метод `check_path()`. Проверяется существование и валидность переданного пути. Код
делается чище и избавляется от повторяющегося кода.

Эти операции позволяют эффективно управлять директориями в создаваемом приложении, обеспечивая при этом безопасность и
корректность выполняемых операций.

Отправить информацию о выбранной заметке в главный компонент.

#### Отправка сообщения

Создается метод, который называется при выборе узла (ноды): `on_tree_node_selected()`. Проверить, является ли узел
заметкой (проверка на суффикс _.md_). Создается класс-сообщение, который будет содержать путь к выбранной заметке
(`note_selected`). Используется метод `post_message()` для отправки этого сообщения наверх.

#### Получение сообщения в главном компоненте (_main.py_)

Добавляется метод с правильным названием для автоматической обработки сообщения. В _Textual_ по соглашению используется
правильное название метода _on_file_tree_widget_note_selected_ (on - ждем событие, file_tree_widget - какой виджет
слушается, note_selected - что слушается). Используется метод `notify()` для уведомления о получении сообщения.

#### Тестирование

Проверяется работа через перемещение по дереву и выбор заметки, чтобы убедится, что сообщения правильно отправляются и
обрабатываются.
